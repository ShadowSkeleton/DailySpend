## Findings

No data-loss or corruption finding. Notes:

1. **Cosmetic, mixed versions:** 1.0 shows notes saved by 2.0 scans, Quick
   Add, and Siri in full (several lines) in its lists. Data is intact; this
   is said in the tester workflow.
2. **Apple doesn't promise data carries over to a beta.** Its TestFlight page
   says only that the beta "will replace" the App Store app. The local
   evidence above shows the store opens in place; the tester messages still
   require a backup first.
3. **Archive signing:** the local archive is development-signed
   (`aps-environment = development`, no
   `com.apple.developer.icloud-container-environment`). Distribution signing
   during upload sets production. Check the uploaded build's entitlements in
   the TestFlight build details.

| Upload to App Store Connect / restricted TestFlight (owner and a few backed-up testers) | **PASS** | Same storage contracts; genuine on-disk 1.0 → 2.0 → 1.0 → 2.0 cycle keeps every record; backup format unchanged; Release archive identity checked | Upload is your action; this review doesn't upload |
| Broad TestFlight / public App Store release | **HOLD** (missing evidence, no defect) | Simulator on-disk cycle above, plus owner-reported device checks (TestFlight build over App Store 1.0 and back, mixed-version iCloud sync, 2.0 backup restored in 1.0, iOS 17/18 launch), reported October 28, 2026 | Tie the owner's device results to a build: record the TestFlight build number (2.0 (16)), that it was archived from `cd389ed` or later, and that its build details show the production iCloud environment. Then this gate can move to PASS |

Recovery if something goes wrong: stop using the build, don't delete the
app, install the other version over it (both read the same store), and
restore the pre-install encrypted backup with **Safe Merge** only if records
are missing.
