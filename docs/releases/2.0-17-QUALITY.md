## What changed since 2.0 (16)

1. **Categories above the keyboard** (tester report, iPhone Air, iOS 27.2:
   the number pad hid the categories, so people had to dismiss it or scroll).
   Cause: 2.0 put the Quick Add card above the amount card, so the category
   grid moved under the keyboard; 1.0 had the amount first. Fix: on the first
   keystroke in the amount field, New Expense scrolls the amount card to the
   top, once per sheet. Quick Add is still visible when the sheet opens and a
   short scroll up after. Edit Expense (no Quick Add) is unchanged.
2. **Rescan guidance after a receipt scan** (owner report: Apple
   Intelligence sometimes misreads a receipt, and a rescan usually fixes it).
   The model runs with greedy decoding, so the same photo always gives the
   same answer; a rescan changes the photo and therefore the recognized text.
   Every result is already checked against the receipt text and its totals,
   with one hinted second read when the checks fail. The pipeline is
   unchanged. The banner now says so:
   - Every scan: the fine print adds "If something looks off, scan the whole
     receipt again." / "如有不对，请重新扫描整张收据。"
   - When a check fails: a tip under the warnings, "Try scanning again: lay
     the whole receipt flat in good light with all four edges in view. A
     fresh scan usually fixes this." / "试试重新扫描：把整张收据平放，光线充足，四边都拍进去。重新扫描通常就能读对。"
     The fine-print sentence is left out then, so it isn't said twice.
3. Build number 16 → 17, plus Xcode 27.1's project-format edits (see the
   data-safety report).

The new test's first run failed on iPhone 17e. The app was right (the
category row moved above the keyboard), but the test required the whole
category button, name included, to be above Save. On the 17e, the smallest
current iPhone, the icons sit above Save and the names just under it. The
test now checks that the first row is above Save and tappable, and then taps
it. No app code changed between the runs.
